# GameTime — 多遊戲活動與期限管理系統

**GameTime** 是一款專為多遊戲玩家設計的 Local-First（本機優先）活動日程與期限管理網頁工具。目標是將分散在各官方公告、版本前瞻與社群貼文中的版本更新、角色／武器卡池與限時活動集中管理，透過日曆檢視、重疊分析與本機公告解析，協助玩家精準掌握每一項期限。

---

## 解決的核心痛點

1. **資訊分散**：同時遊玩多款遊戲時，各遊戲的前瞻與卡池排程散落各地，難以一眼掌握近期重點。
2. **日期分階段公布**：官方常在前瞻只先公布活動名稱、後續才釋出確切日期；本系統原生支援「日期未知（待公布）」狀態，後續補入公告時可自動比對更新，避免重複建檔。
3. **排程撞期盲區**：透過跨遊戲活動重疊分析，快速找出同時進行最多活動或集中截止的日期，合理分配遊玩時間。

---

## 核心設計原則

- **本機優先、免登入**：個人使用為主，無需會員系統；遊戲、活動與版本紀錄皆透過 IndexedDB（Dexie.js）儲存在瀏覽器本機，重新整理不會遺失。
- **零付費 AI 依賴**：不串接任何付費 AI API，公告文字解析、圖片 OCR 辨識與活動比對皆於本機完成，並強制保留人工確認步驟。
- **明確的日期與時區模型**：採用 `date-fns` v4 搭配 `@date-fns/tz`，並明確記錄日期、時間、時區與日期精度，徹底解決跨日偏移與換池時間落差問題。
- **核心邏輯解耦與可測試性**：將日期計算、公告解析、名稱相似度配對、重疊統計與行事曆匯出獨立於 `src/core/`（零 React／DOM 依賴），搭配 Vitest 單元測試驗證正確性，同時保留日後獨立抽離為 npm 套件的彈性。

## 最終技術架構

| 類別 | 技術選型 | 用途說明 |
| :--- | :--- | :--- |
| **前端介面** | React 18, TypeScript, Vite, Tailwind CSS, Lucide React | SPA 互動介面與深色系 RWD 版面 |
| **核心邏輯** | `src/core/`（純 TypeScript） | 日期與時區運算、公告解析、防重複配對、統計分析、資料匯出 |

| **部署與代理** | Cloudflare Workers（Static Assets）+ Wrangler CLI | 靜態前端託管與受控的網址匯入 API 路由 |

## 日期與時區資料模型規範

為正確區分「只公布日期（如 `11 月 25 日`）」與「公布精確換池時間（如 `11 月 25 日 12:00`）」，活動時間欄位須明確保存以下結構：

- **日期（`date`）**：明確字串 `YYYY-MM-DD`（未公布時為 `null`，嚴禁填入假日期）。
- **時間（`time`）**：可選字串 `HH:mm`（如 `11:59`、`03:59`）。
- **時區（`timezone`）**：IANA 時區識別碼或標準偏移（預設承襲所屬遊戲設定，例如 `Asia/Taipei` / `UTC+8`）。
- **日期精度（`precision`）**：明確區分為 `unknown`（尚未公布）、`date`（僅日期）或 `datetime`（精確到時分）。

## 開發路線圖

### 第一階段：網站架構與核心資料管理
- [ ] **網站骨架與導覽**：深藍／深灰主色搭配紫、藍、青輔助色之側邊欄導覽介面，桌面優先並支援手機瀏覽。
- [ ] **遊戲管理（CRUD）**：不限遊戲數量，支援新增、編輯、刪除、搜尋、自訂識別色、伺服器／地區、預設時區、目前版本、版本發布日與隱藏切換；刪除前檢查關聯活動並提示確認。
- [ ] **活動管理（CRUD）**：涵蓋角色卡池、武器卡池、復刻卡池、限時活動、限時任務、版本更新、其他；支援無日期建立（待公布）、日期補齊後自動判定狀態，嚴格隔離不同遊戲之同名活動。
- [ ] **首頁總覽（Dashboard）**：即時呈現遊戲數、活動總數、進行中、即將開始／結束、待公布與近期更新紀錄（首次開啟提供可刪除之範例資料）。
- [ ] **活動列表**：支援關鍵字搜尋、遊戲／類型／狀態篩選與日期排序；無日期活動明確標示「尚未公布」。
- [ ] **IndexedDB 持久化**：以 Dexie.js 建置 `version(1)` 並預留後續升級結構。

### 第二階段：多遊戲日曆、倒數與重疊分析
- [ ] **多遊戲活動日曆**：支援月檢視與週檢視、跨日／跨月區間顯示、點擊檢視當日與活動詳情，妥善呈現單邊日期與待公布活動區塊。
- [ ] **左側動態遊戲篩選欄**：從 IndexedDB 動態生成遊戲核取方塊，支援多遊戲複選、全選／取消、搜尋遊戲，並與活動類型、狀態、日期區間複合篩選且跨頁保留狀態（手機版收合為抽屜）。
- [ ] **精準活動倒數**：依時區與日期精度動態計算距離開始／結束與已進行天數，未公布日期不顯示虛假倒數。
- [ ] **活動期限重疊分析**：以 Recharts 呈現目前同時進行數、未來 30 天每日分布長條圖、時間軸、高峰截止日與各遊戲比較。
- [ ] **版本管理與歷史紀錄**：每款遊戲支援多版本管理與活動歸屬，永久保留舊版本歷史資料。

### 第三階段：智慧公告匯入與資料備份
- [ ] **公告匯入中心**：整合「圖片匯入」、「文字匯入」、「網址匯入」三大入口，匯入前先指定所屬遊戲、版本與公告類型。
- [ ] **圖片匯入與本機 OCR**：支援上傳 PNG / JPG / JPEG / WEBP 與 `Ctrl+V` 剪貼簿貼圖，透過動態載入 `Tesseract.js` 辨識繁中、簡中、英文與數字，提供進度條與文字人工校對。
- [ ] **文字公告解析引擎**：純本機正規表示式與日期規則引擎，支援多格式日期、跨月區間、無年份推算（標記待確認）與純名稱待公布活動擷取。
- [ ] **網址匯入與降級方案**：支援讀取公開公告正文；遇未在允許清單內、CORS 限制或動態渲染頁面時，清楚顯示原因並引導改用文字貼上、圖片 OCR 或上傳 HTML/TXT。
- [ ] **活動自動配對與重複檢查**：依所屬遊戲、版本、類型與名稱相似度比對既有活動（不跨遊戲／跨版本誤併，低相似度不自動覆蓋）。
- [ ] **批次確認與來源紀錄**：所有解析結果皆須經確認表格審核（新增／更新／忽略／微調）才寫入資料庫；更新時顯示欄位差異並保護使用者手動修改紀錄，同步保存完整匯入日誌。
- [ ] **資料匯入與匯出**：支援全站 JSON 匯出與驗證匯入（提供覆蓋還原與智慧合併模式）、活動列表 CSV 匯出（含 UTF-8 BOM），以及標準 iCalendar（`.ics`）匯出（僅輸出具備完整開始與結束日期的活動）。

### 第四階段：Cloudflare Workers 部署與選用擴充
- [ ] **Cloudflare Workers 部署**：使用 Workers Static Assets 整合部署 React SPA 與受控的網址匯入 API 路由（`/api/fetch-page`）。
- [ ] **核心邏輯獨立打包（選用）**：視專案需求將 `src/core/` 抽離並發布為獨立 npm 套件。

## 隱私邊界與 Cloudflare Worker 安全規範

### 資料流向與隱私區分

| 功能模組 | 執行位置 | 資料是否離開本機裝置 |
| :--- | :--- | :--- |
| **遊戲、活動、版本與匯入日誌** | 瀏覽器 IndexedDB | 否（完全儲存在本機） |
| **圖片 OCR 辨識（Tesseract.js）** | 瀏覽器本機運算 | 否（僅初次下載公開語言模型檔） |
| **文字公告解析與防重複配對** | 瀏覽器本機運算 | 否（完全本機執行） |
| **網址匯入（第四階段 API）** | Cloudflare Worker | **是**（僅傳送目標公告網址由 Worker 擷取正文，不儲存內容） |

> 清除瀏覽器網站資料前，請先透過「設定與資料管理」匯出 JSON 備份。

### Cloudflare Worker 網址匯入安全規範
網址匯入 API（`/api/fetch-page`）嚴禁成為任意開放代理（Open Proxy），實作時必須遵守以下安全限制：

1. **僅允許 HTTPS 協定**：拒絕 `http://`、`file://`、`data:` 等非 HTTPS 協定。
2. **官方公告網域允許清單（Allowlist）**：優先僅放行已登錄之主流遊戲官方公告網域，不單靠簡易正規表示式過濾。
3. **防範 SSRF（Server-Side Request Forgery）**：嚴格驗證解析後主機位址，封鎖私有網段、本機迴路（`localhost`、`127.0.0.0/8`、`10.0.0.0/8`、`169.254.0.0/16`、`::1` 等）與非標準通訊埠。
4. **限制重新導向（Redirect）**：限制最大跳轉次數，並對每一次跳轉目標重新執行網域白名單與 SSRF 檢查。
5. **限制回應大小與逾時時間**：設定嚴格的讀取逾時（例如 5–8 秒）與回應體積上限（例如 2 MB），且僅接受 `text/html` 或 `text/plain` 內容類型。
6. **零資料留存**：Worker 僅做即時擷取與純文字萃取，不將使用者的查詢紀錄或公告內容寫入資料庫或持久化日誌。
7. **未支援網域之降級體驗**：由於使用者可自由新增任意遊戲，若該遊戲官網不在 Worker 網域白名單內，或網站採前端動態渲染（SPA）導致無法擷取，系統將明確提示原因，使用者仍可透過**文字貼上**或**圖片截圖 OCR** 完整使用匯入功能。
